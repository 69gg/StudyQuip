# 独立检索与显式顺序的最小对照

运行 `uv run --locked python scripts/evaluate_retrieval.py`。脚本仅使用临时 SQLite、六段合成中文、三条查询和确定的二维向量，不访问实际教材或模型。每一种方式最多返回 2 条，显式开启两种时按顺序追加并以块 ID 去重；没有跨方式评分。

| 查询 | 仅关键词返回块号 | 仅向量返回块号 | 先向量再关键词 | 先关键词再向量 |
| --- | --- | --- | --- | --- |
| 自由落体 | 1 | 1、2 | 1、2 | 1、2 |
| 行星轨道 | 无 | 1、2 | 1、2 | 1、2 |
| 惯性 | 4 | 1、2 | 1、2、4 | 4、1、2 |

记录来自本次实际运行。顺序的改变只改变分组和首次出现位置，关键词不会因为向量分数而被重排；同块只返回一次。目录概述和概念关系不再参与隐式加权，模型仍能用目录／概念浏览及正文读取工具获取相关上下文。

这些人为向量只验证执行方式、上限和顺序，不能证明真实语义质量或比较模型。第 2 条查询特意没有匹配正文词，并且向量也未表示其语义，返回的 1、2 不是正确证据；不能把结果数量当准确率。模型调用量为零。

`tests/test_question_search.py` 另用临时 SQLite 验证多层题目的分部筛选、科目与题型叠加、每题去重、短语／ANY／ALL、关键词上限、词法转义、已删除和过期解析排除、多维空间隔离，以及编辑期间旧返回拒绝、自动更新与旧题补齐。`execute_search` 和 LLM 工具使用同一独立检索协议；单关键词验证不发生嵌入请求。
