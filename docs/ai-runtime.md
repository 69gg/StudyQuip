# AI、调度与任务执行

所有远程模型请求均由单 worker 发出，包括模型测试、题目生成、教材识别／修订、概述、嵌入，以及需要查询向量的搜索。Web 只创建任务。安装的 OpenAI Python SDK 由 `uv.lock` 固定；协议测试通过该 SDK 的实际响应类型和 HTTP transport 运行，不直接伪造业务对象。

## 模型协议

`ModelProfile.role` 区分 `book_vision`、`book_text`、`question_vision`、`question_text`、`embedding`，默认 `question_text`。前四种生成用途均可选择 `chat` 或 `responses` 协议；`chat` 在协议字段里仍表示 Chat Completions，不再表示模型用途。角色不参与并发桶身份。未设置的采样／effort 参数不发送。`thinking` 为三态：`omit` 完全省略，另两态作为服务商扩展显式发送。

| 调用位置 | 模型用途 |
|---|---|
| 教材图片／PDF 草稿、页面重新识别 | `book_vision` |
| 教材正式修订、目录概述／压缩、建议重新生成 | `book_text` |
| 包含题图或参考解析图片的题目提取 | `question_vision` |
| 纯文本题目提取、讲解／知识点／错因优化 | `question_text` |
| 教材索引与查询向量 | `embedding` |
| 模型连接测试 | 指定配置 ID，适用于全部用途 |

用途没有跨教材／题目的隐式回退：缺少对应生成配置时显示用途名称并报错。可选的目录概述在没有教材文本配置时沿用跳过行为，关键词索引仍可用。每个用途独立保留端点、Key、协议、生成参数、预算、窗口及并发；同一用途多条配置仍使用最早创建的一条。

`split_legacy_model_roles(db)` 在 Web lifespan 接收请求前和 worker 认领前自动运行。旧 `vision` 记录保留原 ID 改为 `book_vision`，完整复制一份为 `question_vision`；旧 `chat` 同理拆成 `book_text/question_text`。复制记录使用来源 ID 和用途生成稳定 UUID，嵌入不改变。检测后在单个 `BEGIN IMMEDIATE` 事务内重新读取并拆分，两个进程同时启动不会重复复制或留下半份配置；没有旧用途时不写入。已有记录的历史保留，新用途的后续独立修改／删除不被再次启动覆盖或重新补回。缺少某类旧配置时不猜测另一个模型替代。

仅拆分用途时，请求绑定 HMAC 使用兼容旧 `vision/chat` 分类的规范表示，原模型和协议参数未变则保留旧未完成工具链；真实模型、Key、协议或生成参数改变仍重建未完成单元。配置版本正常递增，已完成结果不会因转换重新调用模型。凭据只在本地配置存储，配置响应不返回 API Key。

Chat 使用 `reasoning_effort`；Responses 使用 `reasoning.effort`。模型的 `max_output_tokens` 为可选正整数，默认 `null`。配置缺省或在表单中清空后，请求完全省略输出上限字段，由服务商采用其默认上限，不发送 JSON `null`；填写正整数时，Chat 映射为所选 `max_completion_tokens`／`max_tokens`，Responses 映射为 `max_output_tokens`。已有配置中的显式数字继续生效，清空并保存即可取消；0 和负数无效。

模型的 `context_tokens` 默认 `null`，表示应用不设置上下文上限：完整请求、教材材料组装、正文读取、概述与嵌入分批均无默认长度回退值。该字段不作为服务商 API 参数发送。填写至少 1024 的整数后，按显式值组织材料并检查完整请求的保守估算，包括提示、工具定义、思考项与工具返回；超限错误显示估算值和设置值，并提示提高或清空该字段。服务商仍执行自身的上下文限制，应用不自动探测模型容量。

Responses 显式 `store=false` 为应用默认值。自定义参数不能覆盖消息、工具、模型和专用表单字段，即使最大输出留空也不能在扩展 JSON 中重新设置其协议字段；内部字段 `context_tokens` 也禁止通过扩展 JSON 发送。允许通过 `reasoning.summary` 等非冲突子字段补充请求。参数不兼容直接报错，不自动删除参数或切换存储模式。

生成必须调用 `submit_result`，由 Pydantic 验证。服务商支持时可开启 strict；第一版默认关闭以兼容第三方服务商。strict 开启后固定字段工具转换为严格 JSON Schema。没有调用工具、空 choices、无效 JSON、参数类型／字段不符或未知工具会带反馈自动重试；自由文本和未通过校验的参数不会作为业务结果保存。

工具选择策略由模型配置的 `tool_choice` 显式决定：`required`（默认）强制调用工具，`auto` 交给模型选择，`omit` 完全不发送此参数；三者都发送工具定义，并要求通过 `submit_result` 和应用侧结构校验。未调用工具时追加明确的用户消息要求调用结果工具，不伪造工具调用 ID。服务商返回参数错误时不自动回退或修改配置。

模型配置 `retries` 在界面中显示为“自动重试次数”，默认 2，0 为不自动重试。网络失败按每次 HTTP 请求计数，格式错误按每个结构化处理单元计数，两者分别使用该值；首次请求不计入重试，因此默认最多三次格式尝试。每次决定格式重试时读取最新次数，复用网络重试的指数退避和请求准入。一个回复内多个工具参数错误只消耗一次格式重试，先保存全部对应工具反馈；格式失败轮不占用 `max_tool_rounds` 的正常工具轮数，防止最后一轮没有修复机会。输出截断、明确的输出／上下文预算不足、无状态续接能力缺失及认证／请求参数错误仍明确失败，不重复发送相同的不可执行请求。

修复反馈包含具体字段路径和错误类型，不回显整份参数或 Pydantic 文档链接。教材 `RevisionDraft.operations` 用 `op` 作为本地判别字段，只校验匹配的操作类型；发送给服务商的 schema 仍使用已有的 `anyOf`，不引入 `oneOf/discriminator`。

AI 结果中的数组类型统一使用 `ModelList[T]`，通过 Pydantic `BeforeValidator` 兼容两种明确的传输编码：只有 `item` 一个键的对象将内部数组展开，单个内部值转换为单元素数组；字符串仅在能被标准 JSON 解析为数组时解码一次。随后仍由原来的元素模型和全部约束校验。带额外键的对象、普通字符串、非 JSON 文本、错误元素、缺失操作类型等不猜测修正，继续使用格式重试。正文、引文和其他字符串字段不做通用 JSON 解码；HTTP 业务输入不使用此兼容层。发给模型的 JSON Schema 保持标准数组及原有形状，原始工具参数完整保留，不原地改写转录。

DeepSeek V4 思考模式使用 `thinking=enabled`、`reasoning_effort=max`；若指定输出上限，字段选择 `max_tokens`，留空则不发送。其思考模式不接受强制 `tool_choice`，应在表单中显式选择“不发送（服务商默认）”；Chat 续接仍完整保留助手消息的 `reasoning_content`。此设置适用于按 OpenAI 格式接入的官方端点，不能通过删除 thinking 来绕过错误。[官方思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)、[官方工具选择兼容说明](https://api-docs.deepseek.com/quick_start/agent_integrations/oh_my_pi/)

Responses 无状态循环保存完整输出项，包括推理加密内容、消息 phase、工具调用及其 ID。后续请求按顺序回传完整项和工具结果；缺少必要推理加密内容时停止无状态续接。`store=true` 用 `item_reference` 引用有服务端 ID 的输出项，不同时回传同一项全文。Chat 保留完整 assistant 消息及第三方的 `reasoning_content`。

每个阶段将初始系统提示、用户提示、图片指纹和工具定义保存为 `request_context`，同时保存完整输出项、待执行读取工具、轮数、格式重试次数及用量。逐个提交已执行的工具结果与剩余 `pending`，并保留原工具批次大小，后续工具中断不会重新执行已经保存结果的工具，也不会把混合调用中的最终提交误当独立调用。格式重试计数、原因和下次执行时间同样持久化，窗口关闭或自动恢复不会重复消耗同一次重试。相同配置和工具结构下的续接复用初始输入快照，不将重新生成的上下文混入原对话；配置指纹或工具结构变化时随未完成工具链一起重建。因此移除识别质量字段后，不会继续发送旧检查点中要求质量判断的工具定义。旧检查点缺少输入快照时，在输入版本校验通过后从持久业务状态重建一次并保存，保留已有转录和工具结果；旧 `repairs` 固定一次限制不再参与新重试计数。图片仍从原文件重建并核验指纹，不在检查点重复保存 Base64；不一致时停止续接。检查点不保存 API Key。

窗口关闭后可以从已有工具结果继续；阶段最终结果已持久化时不会再次调用模型。中断恰好发生在服务商返回与本地检查点提交之间，仍可能产生一次重复请求费用。

## 模型配置热重载

模型记录的 `revision` 随保存递增。worker 按处理用途读取配置，不为整本教材固定一份教材文本配置：每个页修订入口、每次独立结构化调用和每个嵌入批次读取数据库。修改题目配置不影响教材用途，反之亦然；共享模型桶的并发额度仍共同计算。保存配置不要求重启 Web 或 worker；环境变量／`.env` 生成的应用级 `Settings` 仍在进程启动时读取。

| 修改或执行位置 | 生效方式 |
|---|---|
| 尚未开始的识别、修订、讲解或测试 | 开始处理单元时读取最新配置 |
| 已发出的请求 | 按原请求完成，不强制中断、不重复提交 |
| 一个处理单元内的连续工具轮次 | 固定模型 ID、端点、凭据、协议、存储模式、生成参数及上下文边界；下一独立单元使用新配置 |
| 并发、允许时段／时区、超时、重试 | 每次请求／重试刷新；等待并发名额期间最多间隔 1 秒重新检查配置。降低并发不取消已有请求，修改超时不改变已经发出的请求 |
| 已进入 `waiting_window` 的任务 | 保存／删除模型配置时重新设为可检查时间，由 worker 重新判断所有限制；不会提前 `queued` 状态的未来预约 |
| 中断后恢复的未完成单元 | 先读取最新配置，再比较配置指纹与工具结构；改变则从持久业务状态重建该单元，清除旧协议转录／待执行读取工具／轮数／修复次数；保留用量、已提交业务成果和已完成单元 |
| 嵌入批次 | 下一批读取新配置；模型、维度、端点或语义参数改变时，保存已完成批次，以原任务检查点按新空间恢复索引 |

同一工具链不会将旧端点的加密推理项或服务器 item ID 发送到新模型／协议。这一边界遵守 [Responses 推理项续接要求](https://developers.openai.com/api/docs/guides/reasoning)。检查点只保存配置 HMAC、模型名称、配置 ID／版本和协议，不保存一份原始凭据快照。凭据轮换在下一独立单元生效；若旧 Key 已被撤销，正在续接的单元可能失败，重试时按新配置重建。

已经成功持久化的结构化结果不因模型改变而重新生成。恢复时需要重建的单元可能再次收费；数据库幂等不能免除远端重复费用。配置被删除或用途改变时明确失败，不猜测替代角色。降低上下文预算后，超出新预算的必要内容会明确报错，不截断协议项来凑长度。

嵌入空间变化不会将旧批次标记为新空间。写入仍绑定该批次实际使用的配置与实际维度；下一批和最终完成前复核语义指纹，变化则重新规划。轮换 Key、修改并发等不改变语义指纹，仍可复用原向量。重建期间关键词和有效结构检索保留。已完成的教材不会仅因修改配置就自动产生收费任务；需对目标教材执行整理／索引以补齐新空间。

## 并发和时间窗口

凭据身份使用应用持久密钥对实际 API Key、组织、项目及认证范围做 HMAC。模型桶再加入规范化 Base URL 与实际模型 ID；端点保留有效路径。相同桶的角色配置取最小上限，默认每桶 4。

可设置 `credential_max_concurrency`，留空表示没有额外凭据上限。一个 `asyncio.Condition` 原子授予两个层级的名额，不先占一个再等待另一个。取消和异常都会释放两级名额。此机制限制在途请求数，不承诺满足服务商 RPM。

worker 认领和教材草稿识别不叠加固定任务数或页数上限，旧版的 `max_active_jobs=8` 已删除。可执行任务进入异步处理，草稿页可以同时等待模型名额，实际发出的请求统一使用上述两级限制。一个模型配置为 200 时，不会再被单书的 8 页信号量限制；实际并发仍取决于可并行工作量、依赖、时间窗口和服务商响应。草稿结果保持原始输入顺序，之后的正式修订逐页提交。

每天的窗口以指定 IANA 时区解释，默认 `Asia/Shanghai`；支持跨午夜，起止相同或无窗口表示全天。任务预约时间使用 UTC Unix 秒。每次请求、重试及获得名额后重新检查窗口；在途请求允许结束。“立即执行”绕过预约／窗口，仍受两级并发约束。

SDK 自动重试关闭，应用对网络、408、409、429 和服务端错误默认最多重试两次；遵循 `Retry-After`，否则退避。认证、参数等错误直接失败。等待窗口时释放模型名额并将任务设为 `waiting_window`，保存下次可执行时间。

## 持久进度与重复提交

未结束状态为 `queued/running/waiting_window/waiting_review`。相同资源、相同任务类型的提交在 `BEGIN IMMEDIATE` 中检查并复用现有任务，返回原 ID 及 `reused=true`。教材整理与索引共用互斥组，题目识别与讲解共用互斥组；组内不同类型冲突返回 409。页识别、建议重新生成和模型测试按各自资源去重。恢复旧任务前也检查是否已有替代任务。内部从教材整理原子衔接到索引是受校验的后续任务例外。

语义／混合检索按规范序列化的请求去重；PDF 导出按请求和当前题目版本去重，资源创建与任务写入同事务。已有预约不会被重复提交悄悄改期，需要在任务页显式调整。已结束任务允许创建新一轮处理。

`POST /api/jobs/{id}/resume` 将失败、取消或待人工处理的原任务重新排队，保留 ID、检查点、已完成单元和累计用量，不创建新任务。支持 `ScheduleInput` 的延迟、指定时间和窗口绕过；旧 `/retry` 是兼容入口，也读取预约请求体。再次提交已排队／运行／等待时段的同一任务只返回 `reused=true`，不改变第一次续接的时间或租约；已完成任务拒绝续接。恢复事务检查同一资源的互斥任务、来源删除及已有输入指纹，问题返回 409 且不改检查点；实际执行与提交仍做版本和租约校验。

格式重试耗尽时，在该未完成阶段保存 `format_failure`，已执行的工具反馈完整落盘后才使任务失败。用户明确继续处理或将已结束任务重新排期时，只清除耗尽阶段的失败标志和本轮重试额度，保留转录、错误反馈、累计用量与已完成阶段；自动租约／窗口恢复不刷新耗尽额度。续接先读取最新配置，相同配置及工具结构下优先重新校验最后一次被拒绝的独立 `submit_result`。若新的数组解析规则使其通过校验，直接返回结构化候选并走原有业务提交与租约／版本校验，不发模型请求、不增加用量；仍无效则从已有反馈继续重试，不立即再次失败。失败任务在用户点击继续之前仍保持失败状态。

每个阶段在孤立的结果提交校验前保存原始 `rejected_result:{call_id,name,arguments}`，包括 `store=true`；较新的模型回复将旧候选清除为 `null`，未完成工具批次不能通过此入口跳过。恢复时配置／工具结构变化则随旧协议记录清除候选。只有缺少该字段的旧 Chat 检查点才从最后一对独立工具调用／错误结果中恢复参数，且必须匹配 call_id，避免重新采用被新回复替代的旧候选；旧 Responses 若仅有服务端 item 引用而无原始候选，则沿用正常续接。成功重验记录 `result_recovered_from_call_id`，原始转录不删减，也不重做已执行的读取工具。无需数据库迁移，不主动重开当前已失败任务。

任务投影提供 `resume.available/has_saved_progress/reason`。任务页与教材详情对有保存进度的任务显示“继续处理”，没有保存结果时显示“重新执行”；教材详情优先继续最近的整理／索引任务。旧待校对页恢复为草稿后仍按原顺序整理，不标为跳过。

`GET /api/jobs` 返回最近 100 个任务并补全更早的所有未结束任务。页面只接收进度投影，不返回原始检查点、完整模型转录、图片 data URL 或租约凭据。教材识别／正式整理进度按当前数据库页状态计数，待校对、跳过另列；正文与概述数量反映当前教材，历史任务行不代表历史内容快照。嵌入显示当前索引空间的已完成／总项数。跳过页不冒充成功识别页，不制造整本耗时百分比或预计完成时间。

请求活动分别记录等待名额、请求中、等待重试和工具处理，包含当前单元使用的模型与配置版本；格式重试另显示当前次数／额度，等待时显示校验原因。用量来自已记入检查点的响应，包括格式不符的返回以及查询与教材嵌入；不代表服务商最终账单。`last_activity_at` 由业务检查点更新，租约心跳不刷新这个字段。运行中但租约已过期时提示等待 worker 恢复，仍阻止再次提交。前端状态加载失败也保留阻止提交的状态。

## 长任务和教材顺序

每个认领任务独立创建心跳协程，覆盖等待教材互斥锁、网络推理、媒体转换、PDF 导出和数据库检查点。阻塞处理移出事件循环；PDFium 由媒体模块隔离在子进程。续租失败即取消本次处理，所有业务提交仍由 JobStore 校验租约令牌。

worker 收到 SIGTERM（Windows 启动器使用进程组 CTRL_BREAK_EVENT／SIGBREAK）后设置停止事件，停止认领并取消在途任务，等待任务清理后释放数据库和文件锁；网络与浏览器异步上下文随取消关闭。已开始的同步媒体工作在线程／子进程中完成清理，不通过强杀跳过文件发布校验。页面识别和建议重新生成会从来源记录解析父教材，在请求前及每次提交事务内复核父教材仍存在且未删除。

同一本教材的正式修订／索引在 worker 内互斥，页识别草稿可以并行。每个正式处理单元使用当前草稿、有限近邻、目录祖先和工作记忆，工具定义一并计入预算。`current_node_id` 与滚动摘要随操作组提交；节点必须在本次完整模拟后的目录内。操作组回执与 `completed_units` 在同一事务写入，防止中断后重复插入或重复建立概念。

新修订单元的提示明确：`current_page.text` 已包含本次草稿，原页 ID 仅作为来源，目录 ID 与正文块 ID 不互换；只插入新正文且已有材料足够时直接提交，无需反复浏览目录或读取尚不存在的块。修改已有正文仍须读取最新块及版本。旧未完成工具链继续保留其初始提示，进入下一新单元时使用新提示；读取失败的工具反馈同时说明各类 ID 的边界。

请求预算与教材上下文共用离线估算函数：文本／JSON 采用 UTF-8 字节数的保守预算，图片按模型配置的 `image_tokens` 预留。它不是模型的精确计费 token 数；实际用量以服务商响应为准。首次请求不会下载 tokenizer 文件，避免额外网络依赖或阻塞任务心跳。

教材正式修订、概述分段与合批、嵌入分批直接使用模型 `context_tokens`。`null` 时，`ContextBuilder` 不按 token 拆页、裁剪近邻／工作记忆或拒绝正文读取；概述、嵌入也不因隐含长度预算拆批。原页顺序、相关前后文和概述批量数量仍用于组织工作，不自动累积整本前文。`Settings.context_tokens`、`effective_context_tokens` 与旧环境变量 `STUDYQUIP_CONTEXT_TOKENS` 已移除。显式填写模型预算时，材料与完整请求分别按该值检查；Chat 思考内容和 Responses 加密推理项不被裁剪。

只有显式填写上下文预算时，教材组装才预留输出容量；最大输出未填则使用 `Settings.output_tokens`（默认 4096）作内部预留，不补写模型配置或 API 输出参数。上下文留空时不执行这项预算扣减。上下文估算字段本身计入材料大小，不再在组装完成后附加固定余量而触发误拒。省略输出参数时，实际输出仍受服务商默认值和模型限制。

概述按内容指纹缓存，按目录深度自底向上处理。同层多个节点可合为一次请求，默认每批最多 8 个节点。仅有显式上下文预算时才按长度拆分并压缩；留空时各节点完整材料进入批次。分段缓存及请求检查点包含该段文本指纹，配置改变划分方式后，旧首段概述不能冒充完整节点概述。需要压缩但概述未缩短时停止额外调用。`extra_processing_budget` 限制该索引任务成功返回的概述请求数，每轮请求前检查；网络失败是否由服务商收费无法由本地用量确定。正文及 FTS 已提交后，即使预算耗尽仍可使用。

嵌入写入按空间指纹、实际维度、对象版本隔离。重新索引会复用数据库中仍有效的向量；轮换 API Key 不改变空间指纹。没有嵌入配置时教材保留 `embedding_pending`，关键词检索可用。

识别工具只要求 `text` 与可选 `is_blank`，不再要求 `quality/issues`，不做质量分级、改变输入的补救调用或据此暂停。旧返回或已完成检查点中的质量字段兼容读取后丢弃，成功结果直接写入 `text/recognition_draft` 并设为 `draft`。页尾未完句视为正常跨页，保留可见内容，跨页整理交给教材文本模型。格式／网络错误仍按原协议处理；用户仍可手工校正、重新识别、跳过或显式使用 PDF 可提取文字。

worker 启动且尚未认领任务时，`JobStore.restore_review_pages()` 扫描未删除教材的旧待校对页，逐页短事务调用 `TextbookService.restore_review_page`。人工修改优先，否则使用已有 AI 草稿，缺少候选时保留当前文字；空串候选合法，原件和历史不删除。只因旧页面质量原因处于 `waiting_review` 的整理任务会重新排队，预约与检查点保留；其他人工等待、失败和取消不自动重开。转换幂等且不调用模型，继续任务时若仍遇到旧待校对状态也复用同一转换。跳过／人工校正／成功重新识别共用 `JobStore.wake_book`，优先复用该书已有活动或待审任务。

纯文本原件按正文哈希识别，改书名不会重复导入。原件排序变更会更新全局页面顺序；已完成页面的相邻关系改变时记录 `order_changed`，保留原正式内容，后续整理使用新的相邻关系并遵守人工保护。内部 `index` 为整本输入顺序，`page_index` 仅用于定位原 PDF 页，不能混用于排序或对外引文。

## 题目和证据

题目提取在同一次结构化调用中整理题干与选项的公式，既处理图片识别，也处理已有非空题干。提示词要求只规范排版，不润色叙述、纠正题目、补条件或改变数值、变量、正负号、单位与数学含义；行内 `$...$`、独立 `$$...$$`，化学式使用 KaTeX mhchem 的 `\ce{...}`，不自行配平。其余非空字段保持原值，备注和错因原文不可改写。此语义约束由模型执行，应用不声称能够自动证明改写等价。

`QuestionDraft.formatting_issues` 为问题列表，元素包含 `field(stem|option)`、可选 `option_id` 和 `message`，无问题必须返回 `[]`。标记有问题的已有题干或对应选项完整保留；未知或缺失的选项定位保留所有已有选项。模型返回的选项 ID 集合不完整或重复时保留原选项，并记录核对提示；有效结果按原 ID 合并，原顺序及答案对应关系不变。只有全部选项为空且尚无答案的占位列表可按原图重建。空原字段仍可保存忠实识别的草稿并展示提示，不将任务置为质量等待或追加模型请求。

`formatting_issues=null` 或缺少该字段表示旧生成结果，不改已有题干或选项，兼容升级前已缓存的工具结果。新结果的提示持久化为题目只读字段 `formatting_warnings`，编辑器及预览旁展示；人工修改题干或选项后清除旧提示。内容变化或出现核对提示时撤销答案确认，旧讲解标记过期；原件、用户答案、原作答、备注、错因和旧版本均保留。确认答案并不触发额外模型调用。

正确答案候选仅接收来自用户参考资料的提取，始终保持未确认；讲解任务复用题型完整性校验并要求答案已确认。执行期间题目版本变化或题目／教材被删除时，旧任务不能提交。公式整理属于 worker 代码更新，已运行的旧 worker 不会热加载新提示词，需要用户下次启动新版 worker；模型配置热重载不包含代码热重载。

讲解包含 `summary`、`steps`、`knowledge_points`、`citations`、`has_textbook_evidence`、`answer_conflict`、`error_reason_optimized`。引用在提交事务中验证当前块版本与规范化原文，书名和目录路径由服务端生成。模型不能替换用户确认的答案；有冲突只显示说明。检索工具的书本、目录、概念、关系和原文读取均受允许教材集合限制，目录未指定深度时不人为限定树深度，返回仍受分页和上下文预算控制。

`error_reason` 为用户填写的做错原因，默认空白；`optimize_error_reason` 默认 false。仅当开关开启且原文非空白时，生成讲解的同一次工具调用要求返回非空 `error_reason_optimized`，按统一配置进行格式修复重试。提示要求仅优化用词和条理，保留原意、第一人称及不确定程度，不从题目或教材推断新的错因。原文始终原样保存。未开启或原文为空时，服务端强制丢弃模型擅自返回的优化文本；题目识别也不能生成原始错因。修改原文／开关遵循题目版本检查和旧讲解过期规则，正确答案确认状态不受影响。没有新增独立润色任务，预约、窗口、并发和重试均复用讲解任务。

## 验证边界

必要夹具覆盖双协议工具续接、三态参数、可配置的格式重试与耗尽续接、两级并发取消释放、跨午夜窗口，以及阻塞工作期间续租和失租取消。可选上下文预算检查缺省／`null` 不限制完整请求、材料组装和正文读取，长节点概述及嵌入不按默认 token 数拆批，实际请求不携带内部字段；超过显式上限时不发请求。另用 Chat／Responses 夹具验证较长的思考／加密推理项从检查点原样续接。真实临时库验证旧待校对页启动恢复、人工文字及预约保留；并行页识别样本验证旧质量标签不引发补救调用或阻塞。串联流程覆盖正式操作、概念／FTS、概述、题目提取、人工确认和有原文引用的讲解。

这些测试证明请求格式和应用状态行为；没有真实模型 API Key 时，不声明模型识别质量或服务商兼容性已经实测。真实移动端拍照、三平台运行时和 PDF 视觉验收由对应交付文档记录。

热重载样本在双协议工具链中修改配置，验证当前链保持原配置、恢复未完成单元时不混用协议、完成结果不会重发；真实临时库另验证等待并发时提高上限、修改窗口不提前预约，以及嵌入模型／维度切换后按新空间恢复。重复请求、刷新后的进度投影和旧租约提交保护共用跨进程任务样本，不为普通 CRUD 增设覆盖率目标。

用途拆分使用 Web 先启动／worker 先启动两种临时库样本，覆盖同时检测、全字段复制、嵌入不变、重复启动及独立修改／删除；API 返回不含凭据。原续接样本加入旧 `chat` 配置升级，完整工具历史仍复用。串联流程对教材修订、概述、纯文本题目、参考图提取和讲解检查实际发送的不同模型 ID，并行教材图片样本使用专属图片模型；四种用途共享模型桶的规则复用并发测试。
